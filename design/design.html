Diagram 2 · the new design (option 3)

Two small files per Claude session; the rest computed on call

agent-tracker writes only what nobody else keeps and a crash would lose: where each Claude session runs (pane, PID, folder) and its lifecycle (each start, resume and end). Prompts, answers and their times are already in the transcript: they are read when someone asks, never copied. agent-resume's search index stays in agent-resume; usage and quotas are part of agent-tracker (Scope, below).

What each command reads (frequencies: Use cases, above)

agent-tracker now            (you: the visibility view)
  for each data/sessions/<uuid>/ whose lifecycle's last event is a start of the current boot:
    alive?      pid running AND its start time == pid_start          (a reused PID does not count)
    where?      pane_id → its place now (tmux list-panes)
    busy/idle?  ~/.claude/sessions/<pid>.json                      (live, Claude Code's own)
    last prompt the end of the transcript (≤ 256 KB): last "user" entry

ares tmux, step 1 "what was open at the crash"   (a feature: in agent-resume, reads the files directly)
  prev_boot  = the newest boot_ts that is not the current one
  last_tick  = the newest ts among prev_boot's folders                 (≈ the moment of the crash)
  each folder whose last lifecycle event is a start in prev_boot, with ts ≥ last_tick − 2 min  (killed ones stopped ticking)
  one per pane_id: the newest ts wins                                   (the pane was reused)

agent-tracker check          (you, after an install: visibility of the data itself)
  each open Claude session (Claude Code's ~/.claude/sessions): a start line and a last_seen.json < 2 min old?
  is my-setup's statusLine chained through agent-tracker tick? are the two hooks installed?
  → one line per problem: "no last_seen.json for 3 open Claude sessions: statusLine not chained on this machine"

ares resume (agent-resume)
  for each transcript newer than its index entry (checking all dates: 4 ms): re-read it, update the entry
  then search as today
