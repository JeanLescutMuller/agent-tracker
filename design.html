Diagram 2 · the new design (option 3)

Two small files per Claude session; the rest computed on call

agent-tracker writes only what nobody else keeps and a crash would lose: where each Claude session runs (pane, PID, folder) and its lifecycle (each start, resume and end). Prompts, answers and their times are already in the transcript: they are read when someone asks, never copied. Whether asm's search index and the usage data join agent-tracker is still open (Scope, below); here they stay where they are.

What each command reads (frequencies: Use cases, above)

agent-tracker now            (cc-map, cc-rc, notify, terminal_snapshot, you)
  for each data/<uuid>/ whose lifecycle's last event is a start of the current boot:
    alive?      pid running AND its start time == pid_start          (a reused PID does not count)
    where?      pane_id → its place now (tmux list-panes)
    busy/idle?  ~/.claude/sessions/<pid>.json                      (live, Claude Code's own)
    last prompt the end of the transcript (≤ 256 KB): last "user" entry

agent-tracker open-at-crash  (you, the restore, once after a crash)
  prev_boot  = the newest boot_ts that is not the current one
  last_tick  = the newest ts among prev_boot's folders                 (≈ the moment of the crash)
  each folder whose last lifecycle event is a start in prev_boot, with ts ≥ last_tick − 2 min  (killed ones stopped ticking)
  one per pane_id: the newest ts wins                                   (the pane was reused)

asm resume
  for each transcript newer than its index entry (checking all dates: 4 ms): re-read it, update the entry
  then search as today

Who owns the statusline call

Installing the statusline on a new VM must not drop the tracking

Claude Code runs one statusLine command. That setting is owned by my-setup (modules/claude_config.sh, skill config-ownership) and points to agent-statusline's script. So the tracking must not live inside agent-statusline's display code.

Chained by my-setup (proposed)statusLine = agent-tracker tick | bash statusline-command.sh. tick reads Claude Code's JSON from stdin, writes last_seen.json in the background, and passes the same JSON on to the display. agent-statusline has no tracking code to lose. Without agent-tracker installed, my-setup writes the display alone.
One line inside agent-statusline's scripta rewrite of the display can drop it silently; installing the statusline on a VM decides whether tracking happens.
agent-tracker takes over the settingtwo projects fighting over one key: the last install wins.
